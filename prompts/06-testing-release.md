# Etapa 06 — Testes, documentação e entrega

Implemente unittest com diretórios temporários e fixtures fictícias, sem rede. Execute testes reais. Cubra schema, CLI, busca, orçamento, caracteres acentuados, isolamento, locks em processos concorrentes, revisão obsoleta, falha de escrita, recuperação multi-arquivo, instalação, proteção de caminhos, filtragem de segredos comuns, índice reconstruível, branch divergente, memória vazia, tarefa ambígua e decisões substituídas.

Cenário E2E: A inicia tarefa fictícia de corrigir botão SwiftUI, registra investigação, um teste com resultado e próximo passo; encerra processo. B inicia novo processo, recupera estado dentro de 12.000 caracteres e localiza decisão relevante sem ler transcrição. C executa tarefa diferente em paralelo. Simule duas escritas na mesma revisão; apenas uma deve vencer. Simule interrupção antes do ponto de commit; leitura deve encontrar versão anterior válida ou recuperação consistente. Confirme que instalação não modifica fonte e memória não entra no Git.

README final: instalação, comandos copiados e testados, layout, exemplo de sessão, como trocar de aba, como atualizar skill, troubleshooting, privacidade, limites do orçamento e automações específicas do host. Inclua modelo de checkpoint, matriz de critérios e resultado real de testes. CI opcional macOS/Linux sem segredos nem publicação automática. Não declarar compatibilidade com ferramenta não testada. Não afirmar economia percentual sem medir tokens reais; apresentar comparação de caracteres como proxy.

Entregue versão inicial 0.1.0, changelog e relatório de implementação com evidências. Liste pendências reais. Não faça push sem autorização. Priorize funcionalidade simples; RAG, embeddings, MCP, UI e sincronização remota ficam fora do MVP.
